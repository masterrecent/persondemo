# LangGraph 知识库

## 1. LangGraph 是什么

LangGraph 是 LangChain 团队推出的用于构建**有状态、多步骤、可循环**大模型应用的编排框架。与传统的链式（Chain）调用只能线性执行不同，LangGraph 把应用抽象成一张**图（Graph）**，允许节点之间形成分支、循环和条件跳转，因此非常适合构建 Agent、多智能体协作、人机协同审批等复杂流程。

LangGraph 与 LangChain 的关系：LangChain 提供模型、提示词、工具、检索器等基础组件，LangGraph 负责把这些组件编排成可控的执行流程。两者通常配合使用，但 LangGraph 也可以独立使用。

## 2. 核心概念

### 2.1 Graph（图）

图是 LangGraph 的基本单位，由节点和边组成。图的执行是一次「状态流转」的过程：从入口节点开始，沿着边依次执行节点，每个节点读取当前状态并返回对状态的更新，直到抵达终点。

### 2.2 State（状态）

状态是贯穿整张图的数据载体，通常定义为一个 TypedDict 或 Pydantic 模型。所有节点共享同一份状态，节点通过返回字典来更新状态中的字段。状态的设计决定了各节点之间能传递哪些信息。

### 2.3 Node（节点）

节点是一个普通的 Python 函数（或可调用对象），签名通常是「接收状态，返回状态更新字典」。节点内可以调用大模型、查询数据库、执行工具等。节点名在图编译时必须唯一。

### 2.4 Edge（边）

边定义了节点之间的流转关系，分为三种：

- 普通边：从节点 A 固定流转到节点 B。
- 条件边：根据一个路由函数返回的字符串，动态决定下一个节点。
- 入口边与终点边：START 表示图的入口，END 表示图的终止。

### 2.5 Reducer（合并器）

当一个状态字段可能被多个节点或同一节点的多次执行更新时，需要用 Annotated 声明一个 reducer 来决定如何合并新旧值。最常用的是 `add_messages`，它会把新消息追加到已有消息列表中，而不是覆盖。默认情况下，状态字段是「覆盖」语义。

### 2.6 Checkpoint（检查点）

Checkpoint 是 LangGraph 的持久化机制。开启后，图在每一步执行后都会把状态快照保存下来，从而实现：断点续跑、失败重试、多轮对话记忆、时间旅行（回退到历史某一步重新执行）、人工介入审批。常用的存储后端有内存（开发调试）、SQLite、Postgres 等。

## 3. StateGraph 用法

StateGraph 是构建图的主要类，典型步骤：

1. 定义状态：用 TypedDict 声明状态结构，对需要追加语义的字段加上 Annotated 与 reducer。
2. 创建图：`builder = StateGraph(AgentState)`。
3. 添加节点：`builder.add_node("节点名", 函数)`。
4. 添加边：`builder.add_edge(START, "第一个节点")`、`builder.add_edge("上一个节点", "下一个节点")`。
5. 添加条件边：`builder.add_conditional_edges("源节点", 路由函数, {返回值: 目标节点})`。
6. 编译：`graph = builder.compile()`。
7. 调用：`graph.invoke({"字段": 值})` 执行一次，或 `graph.stream(...)` 流式获取中间过程。

## 4. 条件路由

条件边是实现分支和循环的关键。路由函数接收当前状态，返回一个标签字符串，LangGraph 根据标签映射表决定跳转到哪个节点。例如根据用户意图把请求分发给「规划」「日程」「知识库」三个不同的处理节点，就是典型的路由模式。如果路由函数把流程指回上游节点，就形成了循环，可以用于「生成—反思—再生成」这类迭代式流程。

## 5. 多智能体协作模式

LangGraph 支持多种多智能体架构：

- Supervisor（调度者）模式：一个中心调度 Agent 负责判断意图并把任务分派给各个子 Agent，子 Agent 执行完再汇总。结构清晰，易于扩展。
- 网络（Network）模式：各 Agent 之间可以互相调用，适合松耦合的协作。
- 层级（Hierarchical）模式：Supervisor 之下再嵌套 Supervisor，适合超大规模的复杂系统。

Supervisor 模式是实践中最常用的方案，核心是「先路由、再执行、后汇总」三段式结构。

## 6. 持久化与人工介入

开启 Checkpointer 后，可以用 `thread_id` 区分不同的会话线程，实现多用户、多会话的状态隔离。人工介入（Human-in-the-loop）依赖检查点能力：图执行到需要确认的节点时暂停，把控制权交给人工，人工确认或修改状态后再恢复执行。常用方式有中断（interrupt）与状态更新（update_state）两种。

## 7. 流式输出与可观测性

LangGraph 提供多种流式模式：`values` 输出每步完整状态，`updates` 只输出节点产生的增量更新，`messages` 逐 token 输出大模型生成内容，`debug` 输出最详细的调试事件。结合这些模式可以把 Agent 的执行链路实时展示到前端，提升可观测性。

## 8. 常见实践建议

- 状态字段尽量精简，只放节点之间真正需要传递的数据。
- 列表类字段务必使用 add_messages 之类的 reducer，避免被覆盖。
- 路由函数的返回值要与映射表的键严格一致，否则会运行时报错。
- 图的入口必须显式连接 START，出口必须连到 END，否则编译会失败。
- 生产环境建议开启持久化，便于排查问题和实现断点续跑。
- 调试阶段可以先用内存型检查点，上线再换成数据库型。
